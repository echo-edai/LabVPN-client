# LabVPN 本机诊断与修复计划

审查日期：2026-11-14 至 2026-11-15（Asia/Shanghai）。基线：Git main，已有 3 个未推送提交，工作树干净；已安装版本 0.1.19。本报告仅记录脱敏证据。

## 已确认的现状

- 安装了 LabVPN、Clash Verge、Shadowrocket、EasyConnect；进程表还有 MotionPro 和雷神 helper。安装、后台常驻不等于正在接管网络，不能直接判定冲突。
- 已观察到 LabVPN helper、mihomo、fdu-connect；Shadowrocket 的系统 VPN 条目处于 Disconnected，未观察到 Clash 正在运行。
- `scutil --proxy` 显示 PAC `http://wpad/wpad.dat` 和自动发现均启用；Wi-Fi 的静态 PAC 配置却为关闭、自动发现为开。提示有效状态与持久设置存在差异，需分服务审查来源，不能直接认定 PAC 来自某个应用。
- 默认出口为 en0；已观测校内 SSH 目标经 utun9、198.18.0.1，说明该时刻 TUN 确实接管校内地址。
- 校内 SSH 日志命中 FDUIP → 校内组 → fdu-connect；客户端 SSH 出站配置关闭，和终端经校园 VPN 登录是独立用途。
- 当前校内健康探测只测公网 DNS 223.5.5.5:53，成功不能证明实验室主机 SSH 可达。

## 根因候选与代码证据

| 优先级 | 问题 | 证据及后果 |
| --- | --- | --- |
| P0 | helper 定时删除同名配置存在跨会话竞态 | supervisor.rs 启动 2.5 秒后异步删除 config.yaml；不校验会话、不等待核心就绪。旧任务可能删除新配置，慢启动也可能读不到配置。11-14 21:09 日志期待 9097，核心却监听默认 7890；吻合但尚未完成因果复现。 |
| P1 | 把核心存活当成网络健康 | engine.start 只验证 version 和本地端口；ConnectHero、Sidebar 用 running 展示“已连接”和保护承诺。 |
| P1 | 配置应用与恢复会破坏 SSH | apply_config 完整 disconnect/connect；停 TUN 和 fdu-connect 会断开已有 TCP 会话。watchdog 和用户操作缺少统一事务锁。 |
| P1 | 系统代理管理无所有权与快照 | macos.rs 修改所有服务，覆盖 bypass；断开仅关代理，不恢复之前设置；PAC 未纳入检测，读取端口不检查 Enable 和主机。 |
| P1 | 特权 helper 信任边界不足 | root 使用用户可写的工作目录与配置资产；safe_join 仅拒绝词法路径穿越，未防符号链接；任意 root 核心配置及写入需独立安全加固，尚未做利用验证。 |
| P1 | SSH 出站未固定服务端密钥 | hostKeys 默认空，页面没有配置入口。需要核对所打包 mihomo 版本的空列表行为，并为主机密钥提供固定、校验和变更提示；尚未做中间人验证。 |
| P2 | 自动关闭代理策略粗糙 | pgrep -f 使用正则匹配、TERM 后 KILL；无具体冲突归因；KILL 后不复查即报告残留。 |
| P2 | 错误归因失真 | 核心超时默认归因其他代理占用；无证据引导用户关闭软件。 |
| P2 | 前端设置与运行不一致 | “同时设置系统代理”打开，但 TUN 模式编排实际关闭手动系统代理；界面也未展示 PAC。 |
| P2 | 更新、保存、测试语义混乱 | 截图显示当前 0.1.19、最新发布 0.1.18；这本身符合“没有更新”的版本比较，但缺少本地构建/公开发布来源说明。SSH 测试需区分 TCP、认证和转发；多个保存入口和重复断开入口增加理解成本。 |

## 实施顺序和验收

1. 第一批：改为会话独立配置文件，等待核心真实监听后清理；增加竞态测试；修正系统代理状态解析，显示 PAC 冲突警告；减少错误归因。
2. 第二批：连接、断开、应用、校园切换、VPN 恢复共用事务锁；核心恢复保留现有校园 VPN，修正失败重试计数；普通 UI 偏好保存不触发断网。
3. 第三批：总览明确区分核心启动和实测可用；补核心、国外出口、校园 VPN、实验室 SSH 分层检测；每项记录时间、耗时、失败原因，不用单个绿灯代表全部网络。
4. 第四批：系统代理按网络服务做快照和所有权恢复；冲突管理先检测、再让用户选择；默认不强杀；特权 helper 独立安全加固，固定主机密钥，收紧 CSP 和外部路径打开能力。
5. 体验改版：首屏一个主开关、三项网络状态与“检查网络”；高级配置折叠；把 SSH 页面改称“SSH 出口”，另提供“连接校内服务器”诊断；编辑、保存、应用和可能断开会话的影响清晰显示。

验证：纯逻辑/特权 helper 单测、cargo check/clippy、前端类型检查和构建；实机只读对照 TUN、mihomo SOCKS、fdu-connect SOCKS 的 SSH banner，分别记录握手成功与数据返回。跨网络、睡眠恢复、长时间会话和其他代理竞争需后续实机验收，未验证前不得宣称彻底解决。

## 审查范围限制

已读编排、引擎、平台代理、helper 协议/托管、校园 VPN 健康检查、配置生成及主要前端状态/页面；尚未完成全部依赖审计、更新签名链、安装器、各平台权限与外网渗透验证。外部参考保留原样，所有后续验证结果补入此文档。

## 2026-11-15 复查与第一批修复

### 实机复查

- 08:00:11（Asia/Shanghai）只读扫描了 6 个网络服务：USB LAN、AX88179B、Thunderbolt Bridge、Wi-Fi、iPhone USB 和 Shadowrocket。全部手动 HTTP/HTTPS/SOCKS 均关闭，但残留服务器 127.0.0.1:7897；这不能当作代理已开启。仅 Wi-Fi 自动发现开启。
- 启动项候选包括 app.labvpn.helper、LabVPN、com.arraynetworks.vpnd 和 com.leigod.helper。系统扩展命令返回 0 个；不据此排除所有 Network Extension。没有卸载软件、停系统服务或修改网络配置。
- 同轮校内 10.134.142.226、.228、.145 的 22 端口，经系统当前路由和 127.0.0.1:7897 均收到完整 SSH 欢迎行（25–28ms）；127.0.0.1:11080 均为 ECONNREFUSED。系统路由路径仍可能被 TUN 捕获，不能称为物理直连。该时刻不能认定校园 VPN 正在工作；已有路径可达也不能证明长连接稳定。
- 随后 HTTPS 探测：系统当前路由请求百度返回 200；gstatic generate_204 经系统当前路由和 7897 SOCKS 均返回 204，约 0.12 秒。这些 curl 检查不等价于 Safari 的系统 PAC 路径。
- wpad 主机的系统缓存查询无结果，尚不能归因 PAC 的来源。当前有效 PAC 与 Wi-Fi 静态 PAC 差异仍需专门归因。
- 历史样本 app-2026-11-14-1.log 匹配 48 条 SSH 拨号失败/重试、26 条 KeepAlive 失败/超时、3 条连接 reset。统计是日志行数，不能解释为独立断线次数，也不能把同日轮转文件当成一段连续会话。
- 本轮开发命令继承的环境含 NODE_TLS_REJECT_UNAUTHORIZED=0；下载和前端工具命令已显式使用 1。未修改用户 shell 配置；这属于开发进程环境风险，不能推断所有应用关闭了 TLS 验证。

### 已在源码完成

1. helper 协议升级为 2。独立会话文件 + PID/generation 就绪确认，去掉无条件 2.5 秒删除线程；启动失败、停止和退出清理敏感配置。
2. 连接事务共用锁，自动恢复不再与独立 VPN 操作交错。核心重建保留校园 VPN；账号、凭据和连接参数变化才重新登录。检测规则变化不触发校园 VPN 重新登录。
3. 核心恢复计数保留 10 分钟窗口，短暂恢复不清空次数。失败后自动恢复仍存在状态和重试设计欠缺，未宣称完全修复。
4. 手动代理状态要求 Enable、回环主机和一致端口，使用实际运行端口；启用前要求核心可响应。核心重建前关闭指向旧端口的手动代理，防止重建失败后继续指向死端口。关闭前校验当前端口，但仍只是端口匹配启发式，尚非完整所有权证明。
5. PAC/WPAD 警告写入持久状态面板；总览改为“核心已启动”，设置页不再无条件显示已开启。操作后重新读取系统信息。
6. SSH 测试必须读取完整协议欢迎行，拒绝只有 TCP 握手的假成功；总时限 6 秒，限制读取大小，不发送凭据。
7. 防止异步按钮重复提交；仅改变 UI 偏好时不重建核心；Switch 关联可访问名称和说明。文案保持中英双语，补充统一格式化配置。
